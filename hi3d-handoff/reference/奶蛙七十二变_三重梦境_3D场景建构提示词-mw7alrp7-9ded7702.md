# 《奶蛙七十二变：笑破梦境》3D场景建构与 Three.js 集成提示词

版本：V1.0｜目标：可玩的 Web 3D 喜剧关卡原型

## 0. 使用方式与工具边界

本文件是交给 **Codex / 具有 Blender Python 执行环境的 AI 编程代理 / 自己搭建的 Hi3D MCP 代理** 的工程任务书。

- **Hi3D**：主要使用单图/多图生 3D 生成**独立角色、风车、建筑、石像等资产**。先产生干净的单体参考图，角色最好提供正、背、左右视图，然后交给 Hi3D 输出 GLB。不要把一张复杂场景图直接当作可交互关卡。
- **Blender**：使用 `bpy` 创建可复用地形、模块化场景、道具位置、LOD、碰撞代理，导入 Hi3D GLB 后检查轴向/缩放，完成 `.blend` 与 `.glb` 导出。
- **Three.js**：载入 GLB，创建镜头、玩家、输入、粒子、音频、动画、关卡管理器、碰撞和 UI。
- 此阶段用户尚未提供的「西游化梗怪」模型，全部使用相应尺寸的占位体与明确挂点，待模型到齐后替换；不能自创替代角色并宣称是用户的最终模型。

## 1. 总导演提示词（复制给工程代理）

你是一名同时掌握荒诞喜剧设计、Blender Python、3D 资产集成、Three.js 与前端性能优化的高级游戏技术美术总监。请构建一个可玩的 Web 3D 喜剧游戏原型《奶蛙七十二变：笑破梦境》。

### 叙事和玩法
主角「奶蛙」保持用户已有模型的面部、身体比例、色彩和辨识度；只有饰物、特效和局部动作可以做西游记/堂吉诃德化。第一关位于「西游魔音山」：怪物拦路，奶蛙七十二变，真正分出 72 个实体同屏狂笑，嘴中接连喷出巨大的汉字“嘿”和冲击波，并与原创的猴子般高低起伏笑声形成大合唱。小怪先嘲笑主角，再忍不住一起笑，最终半透明灵魂在头顶飘出，地面在约第 30 秒预制碎裂，所有人坠落到第二层梦境。

第二关是「堂吉诃奶蛙追逃跑风车」：奶蛙穿着不遮挡本体轮廓的歪头盔、持玩具长枪或木勺，追逐长着两只小短腿、会惊慌逃跑的大风车；玩家通过狂笑产生龙卷风攻击，狂笑越强，龙卷风越大。追逐路段按顺序循环三种场景：A 黄金麦田喜剧公路、B 倒挂村庄与逃跑磨坊、C 云海浮岛与风车赛道。三场景应能无缝切换，速度和难度可逐渐增加。地面和道具物理表现漫画化，不血腥、不恐怖。

### 视觉规范
日系夸张 Q 版 3D + 软胶玩具材质 + 鲜艳高对比环境 + 夸张面部表情。画面在能看清操作的基础上极尽荒诞；笑点必须有“预期—停顿—反转—连锁失控”。一级主角清晰，二级妖怪中等突出，背景动画适当减弱。所有字体、UI、笑声文字在 Three.js 层生成，不烘焙进人物贴图。保证摄像机不会遮挡核心动作。

### 技术目标
使用 Vite + Three.js JavaScript/TypeScript。所有独立资产使用 `.glb`，约定 Three.js 世界 Y 轴向上，角色面朝世界 -Z；坐标、缩放在导入后统一。角色根节点标明 `ROOT`, 嘴巴挂点 `MOUTH_SOCKET`, 特效中心 `FX_SOCKET`, 地面碎片 `FLOOR_FRAGMENT_XX`。不要把 72 个高面数、独立带骨骼的高精度角色全部加载到主循环：建议近景 8–12 个真实动画角色，其余为 60–64 个低面数实例化替身/动画烘焙版本，同时保证画面确实可见 72 个奶蛙。持续可见数量由场景遮挡和镜头决定，但实例总数必须精确 72。

按模块提交工程，确保可以用占位资源立即运行。必须提供 README、资产缺失回退、性能统计、Web 演示入口；禁止只有静态渲染图。禁止依赖未经授权的第三方角色模型、配音和声音采样。当前阶段不要求做真实在线多人。

### 交付物
1. `assets_src/` Blender 源文件以及单体资产输入图；2. `public/assets/models/` 优化后 GLB；3. `src/scenes/` 第一层、第二层和转场场景；4. `src/game/` 玩家、输入、攻击、敌人状态、梦境管理器；5. `src/fx/` 笑声波、文字“嘿”、灵魂、碎裂、龙卷风；6. `src/audio/` 原创/合法授权声效系统；7. `README.md` 运行与替换模型指南。

## 2. 场景一：西游魔音山（Blender/场景美术提示词）

创建一座占地约 50×50 米的 Q 版西游妖怪广场。中心有直径约 24 米的青石表演平台，边缘是带有不规则面孔纹理的夸张石柱、猴形破庙、红灯笼、歪斜石碑、铜锣、妖怪旗帜（旗帜上不强制写字）、向上堆叠的钟乳石山、两侧矮石阶。山体轮廓要像一个快要忍不住笑的人脸，环境以翡翠绿、朱红、金黄与薄荷蓝为主。整体白天明亮，加入可控舞台补光而不是恐怖阴森。

石质地板预切 18–28 块几何碎片，每片拥有独立 pivot 与碰撞代理，非实时布尔切割；常态地表无明显大缝。导演触发后，0.8 秒出现裂纹贴花，0.6 秒震动，随后碎片重力坠落，角色掉入独立梦境过渡通道。地板下方预留 20 米以上坠落空间。

环绕中心布置 72 个 `FROG_SPAWN_00 ... FROG_SPAWN_71` 空节点：前中景 12 个、左右 24 个、后景 36 个，保留移动空间和摄像机通道；不能生成为不可分离的 72 只奶蛙合体网格。使用用户上传的奶蛙 GLB 或同尺度占位胶囊。设置 `MONSTER_SPAWN_00 ...` 供西游化的「哔哔拉布 / 咕咕嘎嘎 / 巴巴博一 / 我的刀盾」小怪后续替换，不要提前改变它们的用户定妆。

特效只预留锚点：笑声冲击波、喷出的“嘿”、小妖的灵魂、地面共振、铜锣无接触乱响由 Three.js 运行时实现。输出可编辑 Blender 文件、单独静态环境 GLB、地面碎片 GLB、命名锚点清单。

## 3. 场景二：堂吉诃奶蛙追风车（Blender/场景美术提示词）

总体：玩家在画面后方第三人称追逐镜头中看到「奶蛙」追赶前方长腿风车。不要做固定一张跑道：要做可循环的 35–50 米地形模块，标准跑道宽约 12 米，分左、中、右三条可读路径，接头高度、法线和材质风格匹配。路两侧道具活跃但不能盖住障碍轮廓。风车本体具备独立旋转叶片节点 `BLADE_PIVOT`、奔跑腿节点 `LEG_L/R`、可替换表情节点 `FACE_SOCKET`；场景级风车走路线由 Three.js 控制。

### A. 麦田追风
暖黄色波浪麦田，厚重而滑稽的泡沫云，圆滚滚石头，奶酪形稻草垛，远景由三五台长腿风车一边乱跑一边回头。主风车脚踩尘土、叶片速度与跑速不同步，仿佛慌到失控。左右地形低矮，给玩家清楚的追逐视野。

### B. 倒悬村庄
道路在正常地面上，但村庄房屋倒吊在上方，路灯像面条一样弯曲，面包形石头上下弹跳，磨坊店门自己追主人。风车在跑过村口时突然装作一棵普通树，奶蛙靠近后树冠转起来露出风车叶片，再拔腿逃跑。不要让玩家误判可通行路线。

### C. 云海浮岛
轻盈的粉紫天空，浮空木板路、云朵踏板、半透明彩虹廊桥和像纸折的一样的风车阵。主风车带着滑翔伞逃跑，玩家的笑声龙卷风先把它吹到天上，然后风车叶片变成临时螺旋桨，反而加速逃走。浮岛间可跳跃，不设计随机无法通过的空洞。

每个模块导出独立静态 `.glb`，按模块注册起点和终点连接锚点 `ENTRY`、`EXIT`，障碍物碰撞代理与艺术模型分离，避免用高精度网格逐三角形碰撞。

## 4. 梦境碎裂转场（Three.js/Blender 协作提示词）

制作 4–6 秒的可循环坠落通道：玩家从碎裂石板间掉下，周围是摔落的刀盾、倒着笑的妖怪、故障时钟、会跑的风车剪影、漂浮的破碎窗户以及短暂一闪而过的「另一个奶蛙」；空间从西游暖色快速转为紫蓝梦境，再亮起金黄麦田。

落地前一秒，风车从远处冲来，头也不回地惊慌逃跑；奶蛙落地后自动进入追逐跑酷。过渡可以加载下一段 GLB，但视觉上应先从玩家镜头衔接而不是直接黑屏；加载期间若资源未就绪，使用淡入雾幕和可延展坠落背景，不阻断输入。

## 5. 具体笑点导演规则

- 5 秒内让玩家看到第一处明确信息反差：小妖举盾准备宣战，盾牌抢先抖着笑起来。
- 72 个奶蛙绝不同时做完全同步的相同动作：分 6 个笑声声部，每组随机错相 0.1–0.5 秒；逐层放大到齐声高峰。
- “嘿”使用大字弹性 Sprite 或带透明底的粒子贴片，大小从 0.3 米膨胀到 2 米，发生轻微碰撞后碎成墨滴和星星；避免每个字都生成高精度 3D 字网格。
- 小妖的灵魂出窍效果采用其主体模型的低细节、半透明青蓝色副本，向上漂 1–3 米、回头看自己身体，最终被一声“嘿”弹飞。角色主体保留站立/狂笑动作。
- 追加一个 1 秒反差：唯一没笑的小妖突然被镜头推近，发现它的灵魂已经在天上笑到打滚。
- 风车会“害怕”：回头、加速、打滑、撞倒自己带出的稻草人；主角龙卷风不能一直只造成正向打击，偶尔反让风车借风滑翔，带来追逐反转。
- 每 8–12 秒安排一个可读的视觉笑点；避免常驻满屏乱码、闪烁和巨大音量导致玩家疲劳。

## 6. Hi3D 资产生产：逐件制作，不要一张图生成整关

### 通用制图提示词
“单件 3D 游戏资产参考图，和当前奶蛙游戏统一的夸张 Q 版 3D 软胶玩具风格；几何轮廓清晰、无遮挡、材质与颜色分区明确、背景纯色、全身完整入镜、尽量少阴影、无文字、无水印、无额外物体。角色生成正面、背面、左侧、右侧四张一致比例的视图；同一物体在所有视图上服装、颜色、道具保持相同。”

### 具体单件资产提示词
1. **长腿逃跑风车**：矮胖圆柱磨坊主体，蓬松帽子形屋顶，四片夸张木制扇叶，下面长着两条短小卡通腿与大脚鞋，惊慌的豆豆眼与夸张倒八字眉；结构分成独立主身、扇叶、腿和面部挂点；适合奔跑动画；风格软胶木头混合质感。
2. **西游妖山石柱**：像捂嘴偷笑的石脸轮廓，表面风化纹理轻微，宽底稳定，顶部弯曲，游戏化低中面数，单独物件。
3. **会笑的盾牌**：卡通木盾，中央有一张被压扁的忍笑脸，金属铆钉和边缘简化，柄在背部，单独可移动道具。
4. **铜锣及木槌**：明亮青铜色，锣面表情像被笑声震歪，锣架和木槌分别可拆卸。
5. **龙卷风聚能道具**：青蓝螺旋状泡泡/云线结构，仅提供美术参考；最终实时龙卷风应由 Three.js 粒子/曲线系统生成。
6. **倒悬村小屋**：扭曲童话小木房，屋顶是松软饼干质感，窗眼惊讶，烟囱可分离；不要附带地形。
7. **浮岛踏板**：圆润草地顶面 + 泡芙底座，边缘发光，明显的可落脚中心区域。
8. **半透明灵魂**：优先复用用户小怪模型的轮廓，通过 Three.js 透明材质与轮廓描边创建；不另生成造型不同的新妖怪。

Hi3D 输入：单图模式一张干净图片；多视图模式 2–4 张，必须含正面。生成后输出 GLB，进入 Blender 网格减面与材质检查。保留原始模型，以便重制。

## 8. Three.js 可执行开发任务提示词

“请创建 Vite + Three.js Web 项目，用 GLTFLoader 加载 Blender/Hi3D 导出的 GLB。即使用户模型尚未上传，也必须用程序化基础网格占位并使全部玩法可运行。建立主场景 JourneyScene、追逐场景 RunnerScene、梦境过渡 DreamTransition 与统一 SceneDirector；以数据驱动方式实现剧情轨道和玩家触发事件。第一关镜头为可旋转/轻跟随第三人称；第二关自动前进、左右切换路线、跳跃、笑声攻击。PC 支持 WASD/方向键、Space 跳跃、J 狂笑、K 龙卷风；手机支持大号触屏方向和技能按钮。必须有暂停、音量调整与减少屏幕震动选项。

实现 72 只奶蛙：近景 8–12 只基于 SkeletonUtils.clone 的动画角色，其余使用低面数 InstancedMesh、分组离线烘焙动作或其他 GPU 友好方案；每只具有可追踪编号，导演轨道依序出现，全场数量为 72，动作有相位差。用 AnimationMixer 播放已有动画，缺失动画则以组变换和程序化缩放模拟。技能粒子和字形效果走贴图/Shader/Sprite，不需要 72 组独立昂贵粒子系统。

当所有小怪进入 Laughing 状态且剧情进度达到 30 秒附近，触发碎裂预演，然后使用预制碎片网格按刚体近似运动，地面碰撞关闭，玩家与 NPC 下坠；此时开始后台预载第二层并执行梦境转场。跑酷层包含 3 种可循环重排的 35–50m 模块，循环预生成道路及障碍，永不生成无法通过的路况。主要敌人是可逃跑风车，具有惊恐、加速、被吹飞、借风逃跑四种状态；按冷却机制制造龙卷风，在前进路径里推动或暂时击晕风车。场景每 8–12 秒出现一个情节喜剧事件，但视觉提示不覆盖玩家操控。提供碰撞代理、难度曲线、无障碍音量控制、性能面板和每个 GLB 的加载失败回退。

优先交付能在本机 npm install / npm run dev 中运行的完整最小原型，不要先写一篇无法运行的设计说明。之后分阶段替换 Hi3D 资产。实现 WebGL2 环境下的合理 LOD 和纹理减载，桌面以 60FPS、移动以 30FPS 为目标，不以效果牺牲操作响应。所有音效使用原创或有明确许可的素材，不能直接抓取影视版孙悟空笑声。”

## 10. 验收条件

- 启动项目后无需等待所有最终角色 GLB 就可以进入关卡，加载失败显示清晰占位体与控制台错误。
- 第一层的主场景、72 个分身、可识别妖怪占位、笑声波、喷“嘿”、灵魂出窍、预制石板碎裂和玩家坠落 **都能在实际 Three.js 页面运行**。
- 30 秒转场能进入第二层；三种跑酷模块可以连续循环、没有视觉穿模或不可通过地形。
- 跑酷层至少包含移动追逐、路线切换、跳跃、笑声龙卷风和风车逃跑反应；不是视频播放替代互动。
- GLB、Blender 源、代码、资源清单与 README 全部留存；未到位模型有占位接口和替换说明。
- 使用原创或获授权音效。镜头抖动和闪烁可关闭，不能靠突发高音量制造惊吓。
